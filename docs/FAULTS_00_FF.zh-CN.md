# WHO=00 / FF：先定位到 IMU 枚举，不能先判芯片报废

适用：当前原版五字段日志 WHO、GSEQ、QSEQ、SPIERR、FLAGS。以下以这些字段是可读 ASCII 十六进制值为前提；若串口软件显示的是原始 00/FF 字节且无文字标题，先保存原始日志、检查 115200/8N1/文本模式。

## 1. 现有证据能说明什么

用户报告：一块板返回正常，其他板全零或 WHO=FF 后四项零。没有逐板原始日志、实测电压、制造文件或波形，因此没有确认具体失效器件。正常板是对照样本，不等于已经通过 30,000 次通信或整机验证。

旧固件 `imu_init()` 把结构体清零，等待启动，读取 0x0F；非 0x70 立即返回，未配置时 `imu_poll()` 不采样。`WHO=FF GSEQ=0 QSEQ=0 SPIERR=0 FLAGS=0` 正是可能的结果。SPI 没有 I2C 那样的逐设备 ACK：MCU 时钟发完、收到 00/FF，也可能返回“传输成功”。SPIERR 只统计传输函数错误，**不是 WHO 合格计数或线路通断测试**。

|现象|优先定位|不能据此断言|
|---|---|---|
|可读标题、WHO00、其余零|初始化前/后身份读取失败，MISO低、电源/地/CS/焊接等|不是一定STM32损坏|
|可读标题、WHOFF、其余零|MISO高或浮空、CS未选中、开路、IMU未供电等|不是一定IMU烧毁|
|WHO70、GSEQ增长、QSEQ为0|融合/FIFO、配置、姿态编码及采样阶段|不是同一个WHO问题|
|WHO70但两计数为0|配置读回失败或无新数据|需DBG2阶段和配置字节|
|只有杂乱原始字节|串口模式/波特率/固件不对应|不要套用上述字段解释|

## 2. 优先做 A → B → A 对照

保留正常板 A 的固件与焊接状态，先记录现有 ELF/BIN SHA256、板号、实际 X1/IMU 料号。一次只连接一块 ID200，所有换线都断电（含USB）。使用同一个已正常的电源、线束、适配器、串口参数，测 A、异常 B、再测 A。不得同时并入两块 ID200。

每块至少保存60秒完整日志、正反面照片、供电电流和两路IMU供电测量。若 A 也失效，先查测试台而非返修全部板。如果只有某板失效，制造/焊接/上电差异的可能性上升，但仍需测量。

```bash
# 在完整下载包根目录（capture工具依赖包内Web模块），U2D2接J2，J1保留外部5V
.venv/bin/python scripts/capture_board.py --port /dev/cu.usbserial-实际编号 --board A --seconds 60
.venv/bin/python scripts/capture_board.py --port /dev/cu.usbserial-实际编号 --board B --seconds 60
.venv/bin/python scripts/analyze_log.py logs/A-实际时间.jsonl logs/B-实际时间.jsonl
```

capture先读诊断再读核心，因此坏IMU的健康Alert不会阻止记录身份和初始化错误。无法通过DXL读取时，先用USB-TTL RX→J3.4、GND→J3.1、115200/8N1收完整文本，VCC/TX不接。

## 3. 测量顺序（不盲目回流、不大电流注入）

**断电：**拔除所有USB和电源，确认残压消退。目检U2方向、料号、MLCC裂纹、锡珠、LGA底部疑似焊接。逐网与A比较通断；供电网共用，U1和U2都测到低阻不能定位哪一颗短。U2.5/.6与.7/.8是邻近电源/地，高风险焊桥位置；隐藏焊点需要适当返修/X-ray，不用针尖在带电芯片边缘来回扫。

**上电：**继续5.00V限流单板，初测50mA只作为保守起点；正常板和异常板用同样条件。分别测C7、U1.4就近电容、U2.5 VDDIO及U2.8 VDD的电容/过孔，均应约3.3V；不能只测LDO。U2.6/.7地要通。3.20–3.40V是工程筛查目标，不是厂家保证的另一个规格。持续CC、掉压或异常发热立即停止。慢表正常不排除启动瞬态，用短地弹簧观察电源纹波/复位。

**SPI连通和波形：**

|网络|MCU端|IMU端|
|---|---|---|
|CS|U1.11 / PA4|U2.12|
|SCK|U1.12 / PA5|U2.13|
|MISO|U1.13 / PA6|U2.1 / SDO|
|MOSI|U1.14 / PA7|U2.14 / SDI|

逻辑分析仪设 SPI Mode0、MSB first。WHO事务应为 CS 拉低，MOSI发送 **0x8F + 1字节dummy**，总共16个时钟，再CS拉高；有效0x70在第二字节MISO，不能把命令阶段的MISO当WHO。对比A/B在MCU及IMU两端的CS/SCK/MOSI/MISO，判断是否走线开路或未被驱动。默认4MHz在器件规定10MHz上限内，不能仅凭“速度高”判错；波形边沿/CS建立保持和供电都要看。[SOURCES](SOURCES.md)

CS始终高：IMU未选中；CS始终低：焊桥/固件/复位状态疑点。SCK有而MOSI无命令、或MISO恒高/低，都只是定位线索。微焊接返修前保存证据，**不要把00/FF硬编码成70、不生成假四元数、不屏蔽健康告警**。

## 4. 新诊断固件怎样帮助定位

不改正常板A，先备份异常板原程序与日志，再刷 `firmware/diag-v2-hsi-dxl-spi4/imu.hex`（HEX带地址，使用ST-LINK/SWD并Verify）。版本2保留核心数据布局，增加DBG2区：启动阶段、错误类型、复位前/后各4次WHO、传输有效位、非70次数、实际SPI配置频率。四次连续正确才继续，不是碰到一次70就放行，不无休止重试掩盖不稳定。

|DBG2情况|含义|
|---|---|
|stage2 / error1，history全00或FF|复位前身份不匹配；SPIERR可能仍0|
|stage4 / error1，前4个70后4个异常|传感器reset后身份读取出错；查时序/供电/复位影响|
|error2，valid_mask相应位0|MCU传输函数超时/错误，不与身份不匹配混在一起|
|stage7 / error3|配置读回不符|
|stage8 / error0|配置通过，仍须检查gyro/q序号、age、方向、完整通信|

必要时仅在同一异常板上比较 `diag-v2-hsi-dxl-spi1`（1MHz）与spi4，其他条件不变；1MHz能读而4MHz不稳提示信号/时序余量，**不证明焊接已修好，也不自动转成整机合格**。1MHz的改变是MCU↔IMU SPI，外部DXL始终1Mbps。

## 5. 本轮不能确定的事项

不能凭这条用户描述给出某颗IC必须更换的结论；没有确认具体批次故障率、实际坏板数量、物理根因。供电、CS/MISO、LGA和时序是优先检查方向，不是已证实根因。完整raw日志+电源值+WHO波形是下一步证据。
